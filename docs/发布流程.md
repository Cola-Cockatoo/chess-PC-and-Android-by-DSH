# 发布流程

给仓库主人看的操作手册：怎么第一次上传、以后怎么更新、怎么发版。

---

## 一、第一次上传（只做一次）

### 1. 在 GitHub 建一个**空**仓库

1. 浏览器打开 <https://github.com/new>
2. **Repository name**：`chess`
3. **Description**：
   `简约风国际象棋：Windows 桌面 + 网页 + 安卓 + iOS，同一套规则与 AI；20 档 ELO、25 个开局定式、带引导的复盘课`
4. 选 **Public**
5. ⚠️ **不要**勾选 "Add a README file" / "Add .gitignore" / "Choose a license"
   —— 本地已经有这些文件，勾了会让第一次推送因为历史分叉而失败
6. 点 **Create repository**

### 2. 在本机推送

```powershell
cd "项目所在目录"
git remote add origin https://github.com/<你的用户名>/chess.git
git push -u origin main
```

第一次推送会弹出一个窗口 → 点 **Sign in with your browser** → 浏览器里登录 GitHub 并点 **Authorize**。
这之后 Git 会记住凭据，以后 `git push` 不再问。

> 如果没弹窗、而是在命令行里问用户名密码：**密码不能填 GitHub 登录密码**。
> 去 GitHub 右上角头像 → Settings → Developer settings → Personal access tokens →
> Tokens (classic) → Generate new token，勾上 `repo`，把生成的那串字符当密码粘贴。

### 3. 发版（把 exe / apk / zip 挂出去）

仓库页面右侧 **Releases** → **Create a new release**：

- **Tag**：`v2.8.0`（会自动创建这个 tag）
- **Title**：`v2.8 · 复盘课`
- 把下面四个文件拖进附件区：

| 文件 | 来源 |
| --- | --- |
| `chess-windows.zip` | 仓库根目录（Windows 桌面版，含使用说明） |
| `chess-android.apk` | `mobile\dist\`（安卓） |
| `chess-ios-project.zip` | `mobile\dist\`（iOS 工程，需自己签名） |
| `chess-web.html` | `mobile\dist\`（网页单文件，可离线打开） |

> **必须用英文名上传。** GitHub 网页上传中文文件名会被截断，实测 `国际象棋.apk` 变成了 `default.apk`、
> `国际象棋-iOS工程.zip` 变成了 `-iOS.zip`。先跑 `python tools\rename_release_assets.py`，
> 它会把四个产物复制到 `release\` 目录并改成英文名，再把那个目录里的文件拖进 Release。

- 说明里写两句话（这次改了什么）→ **Publish release**

> 为什么可执行文件不进 Git：clone 会变重、每次重新打包都会多一个提交、历史里塞满二进制。
> Releases 就是专门放构建产物的，README 里的下载表格指向它。

### 4. 装点仓库首页（2 分钟）

- 首页右侧 **About** 旁的齿轮 ⚙：填入 Description；
  **Topics** 填 `chess` `csharp` `winforms` `canvas` `android` `ios` `game` `offline`
- 可选：在 `README.md` 顶部加一行 CI 徽章（推送成功一次后再加，否则图片是灰的）

  ```markdown
  ![tests](https://github.com/<你的用户名>/chess/actions/workflows/ci.yml/badge.svg)
  ```

## 二、以后每次改完代码

```powershell
cd "项目所在目录"
git add -A
git commit -m "说明这次改了什么"
git push
```

想只提交某几个文件：`git add src/Core/Review.cs mobile/web/review.js` 再 `git commit`。

## 三、仓库里已经准备好的东西

| 文件 | 作用 |
| --- | --- |
| `.gitignore` | `dist/`、`*.exe`、`*.apk`、`*.zip`、构建目录、开发截图都不会进仓库 |
| `.gitattributes` | 统一换行，避免 Windows 与 Linux 之间整文件 diff |
| `LICENSE` | MIT（可自由使用、修改、分发，保留版权声明即可） |
| `.github/workflows/ci.yml` | 每次推送自动跑 JS 引擎测试（614 条断言，本地已验证通过） |
| `README.md` | 截图、功能、构建与测试说明 |
| `docs/images/` | 5 张精选截图（约 330 KB） |

当前仓库：**96 个受跟踪文件，0.84 MB**（不含 `.git`）。

## 四、常见问题

| 现象 | 处理 |
| --- | --- |
| `remote origin already exists` | `git remote set-url origin https://github.com/<用户名>/chess.git` |
| 推送被拒（`rejected`，远程已有提交） | `git pull --rebase origin main` 后再 `git push` |
| 改了仓库名 | GitHub 改名后：`git remote set-url origin <新地址>` |
| 想让仓库变私有 / 公开 | Settings → General → 最下方 Danger Zone → Change visibility |
| 想撤销某次提交 | `git revert <提交号>`（安全，不重写历史）后再 push |
| 磁盘上的改动想全部丢弃 | `git restore .`（**不可恢复**，慎用） |

## 五、重新打包发布物（发新版前）

```powershell
# Windows 桌面版
powershell -ExecutionPolicy Bypass -File build.ps1

# 网页单文件（同时同步到 APK 与 iOS 工程）
powershell -ExecutionPolicy Bypass -File mobile\build_web.ps1

# 安卓
powershell -ExecutionPolicy Bypass -File mobile\android\build_apk.ps1

# iOS 工程压缩包
python mobile\make_ios_zip.py

# Windows 压缩包（内含 exe + 使用说明 + 备用网页版）
python tools\repack_zip.py
```
